# 产品需求拆解规范

## 何时使用
用户提出产品想法、功能设想，或说「我想做一个 X」时。

## 流程
1. 先用一句话复述用户想要的东西，确认理解没跑偏。
2. 拆成四块：目标 / 用户 / 最小可用 / 风险。
3. MVP 必须是「3 天内能做完」的版本。
4. 每块不超过 5 条，每条不超过 20 字。

## 硬约束
- 不写「可以考虑」「建议评估」这类空话。
- 每个功能必须能回答「谁在什么时候用它」。
- MVP 里必须有「不做」清单，至少 2 条。
- 不确定的需求写「需要确认：…」，不要替用户决定。

## 输出格式

```
【一句话】
【目标】3 条以内
【用户】谁 / 什么场景
【MVP】5 条以内
【不做】至少 2 条
【风险】3 条以内
```

# 端侧智能体架构（展望）

> 三个需求，一个模型，三个角色。
> 定位见 docs/POSITIONING.md（唯一依据）。

## 总体结构

```
                   端侧模型 bge-small-zh 24MB
        ┌────────────────┼────────────────┐
   角色① 路由       角色② 归一化      角色③ 调度
   这句给谁          整理干净         本地 or 云端
   embedding        小LLM/规则        二分类
```

## 角色① 路由（判断适配哪个模块）

- 实现：模块 description 预计算向量，输入向量化后余弦相似度
- 阈值 0.55，低于不触发，回退关键词打分
- 超过 skill 的点：可判断「已选模块不适配」
- 体积/延迟：24MB / 50ms / 0 token

## 角色② 归一化（散乱 -> 有序）

这是项目定位的直接落地：模块把输入整理好，模型只处理有序部分。

| 动作 | 需要模型吗 | 例子 |
|---|---|---|
| 结构化（切块/编号/去噪） | 不需要，规则 | 乱想法 -> 目标/约束/未知 |
| 提取（要点/实体/字段） | 规则优先 | 附件 -> 标题/日期/待办 |
| 改写（口语 -> 规范） | 需要小 LLM 350MB | 口语需求 -> 结构化需求 |

**别一上来就上模型**：前两个规则就够。

## 模块带智能体

模块不只是「输入改写脚本」，它可以带自己的判断力：

- **模块 = 能力包**：A 侧是知识（reference，模型按需读），B 侧是判断清单（什么算好、什么该重写）。
- **同一模型 + 不同清单 = 不同专家**：换清单就换人格，不用换权重。
- **判断分级**：规则 → 窄模型（24MB embedding / 350MB 小模型）→ 大模型。能规则判的绝不叫模型。
- **路由是前置条件**：5 个模块不能各跑一次，必须先决定「这句给谁」再调用。

## 角色③ 调度（简易本地、复杂云端）

| 层级 | 做什么 | 成本 | 状态 |
|---|---|---|---|
| L0 确定性规则 | 算数/时间/单位 | 0 请求 <1ms | 已实现 |
| L1 本地模型 | 归一化/分类/短摘要 | 0 请求 50-500ms | 待做 |
| L2 云端大模型 | 推理/创作/长文 | 1 请求 1-10s | 已有 |

**升级判断**：先规则（长度/是否含代码/命中本地模板），
再用 embedding 二分类兜底。

## 标签与上下文索引

> 只记录想法，不实现。

- **A 贴标签**：话题 / 意图。服务「这一轮」——检索什么历史、激活哪个模块。
- **B 贴标签**：内容类型（结论 / 代码 / 清单 / 决定 / 待办）。服务「未来所有轮」。
- **检索**：标签粗筛 → 需要时再 embedding 精排。
- **提炼**：先做结构化拼接（取标签段原文），不要一开始就上模型。
- **标签的第三用途**：决定哪些消息落库、哪些显示、哪些触发动作。
- **实施前置**：B 贴标签 + Room 加字段。
- **优先级**：低于「A 的路由」和「规则质检」。

## 模块认知（反馈学习）

> 只记录设计，不实现。本轮只有一条 `[[USED:x]]` 声明和一份日志。

**记录维度**：`(moduleId, moduleHash, queryVector, declaredUsed, formatMatched)`

**三档判定**：

1. 声明了 `[[USED:x]]` → 确实用了
2. 没声明但有该模块的格式特征 → 模型漏声明（质量问题，不是模块问题）
3. 都没有 → 加载了但不适用

**hash 绑定**：`moduleHash = sha256(description + 何时使用节)`；hash 变 → 旧认知 stale。

**用途**：相似场景检索（同一 embedding）+ 路由分数加权。

**前置**：Room 表（本轮不做）。

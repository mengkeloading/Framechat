# 端侧智能体架构（展望）

> 三个需求，一个模型，三个角色。

## 总体结构

```
                   端侧模型 bge-small-zh 24MB
        ┌────────────────┼────────────────┐
   角色① 路由       角色② 归一化      角色③ 调度
   这句给谁          整理干净         本地 or 云端
   embedding        小LLM/规则        二分类
```

## 角色① 路由（判断适配哪个模块）

- 实现：模块 description 预计算向量，输入向量化后余弦相似度
- 阈值 0.55，低于不触发，回退关键词打分
- 超过 skill 的点：可判断「已选模块不适配」
- 体积/延迟：24MB / 50ms / 0 token

## 角色② 归一化（散乱 -> 有序）

这是项目定位的直接落地：模块把输入整理好，模型只处理有序部分。

| 动作 | 需要模型吗 | 例子 |
|---|---|---|
| 结构化（切块/编号/去噪） | 不需要，规则 | 乱想法 -> 目标/约束/未知 |
| 提取（要点/实体/字段） | 规则优先 | 附件 -> 标题/日期/待办 |
| 改写（口语 -> 规范） | 需要小 LLM 350MB | 口语需求 -> 结构化需求 |

**别一上来就上模型**：前两个规则就够。

## 角色③ 调度（简易本地、复杂云端）

| 层级 | 做什么 | 成本 | 状态 |
|---|---|---|---|
| L0 确定性规则 | 算数/时间/单位 | 0 请求 <1ms | 已实现 |
| L1 本地模型 | 归一化/分类/短摘要 | 0 请求 50-500ms | 待做 |
| L2 云端大模型 | 推理/创作/长文 | 1 请求 1-10s | 已有 |

**升级判断**：先规则（长度/是否含代码/命中本地模板），
再用 embedding 二分类兜底。

## 不要做的事

- 不要用 9B 模型做判断（300MB+ 换分类，不划算）
- 不要指望本地模型替代云端（分级，不是替代）
- 不要在 B4 绿之前动这些

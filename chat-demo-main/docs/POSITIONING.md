# 定位（唯一依据）

> 所有功能取舍都以此为准。写不进这一页的功能，先不要做。

## 一、核心命题

MyChat 是**大模型两侧的精修层**。

    用户输入
      ↓
    【A】精修「问题的形态」：归一化、注入专业规范、短路不该问的
      ↓
    大模型
      ↓
    【B】精修「答案的形态」：质检、修正、渲染成产物
      ↓
    用户拿到的东西

两头都在模型之外做功，中间是模型。框架的价值全部在两侧。

## 二、A 和 B 没有高下

| | A（模型前） | B（模型后） |
|---|---|---|
| 精修什么 | 问题的形态 | 答案的形态 |
| 独有能力 | 决定「要不要调模型」 | 决定「产出什么形态」 |
| 价值维度 | 成本、延迟、准确性 | 可用性、可操作性 |
| 典型 | local 短路、输入截断、归一化 | 质检、修正、生成文件/清单/卡片 |

两者都是执行层，共用同一套能力，只是挂载点不同。

## 三、模块是什么

一个模块 = 一个**专业能力包**。

| 层 | 内容 | 赋能什么 |
|---|---|---|
| A 侧 | SKILL.md（领域知识） | 「怎么做」 |
| B 侧 | 判断清单（质量标准） | 「做得对不对」 |
| 将来 | 小智能体（窄领域判断执行器） | 把清单自动跑起来 |

三种判断强度：提示 / 修正 / 重来。

## 四、与 skill 的关系

继承：包格式兼容，skill 文件夹改 9 行 MODULE.md 即可装载。

超越（skill 结构上做不到）：

| 维度 | skill | 本框架 |
|---|---|---|
| 触发 | 模型自主决定 | 模型 + 本地向量，双路 |
| 输出侧干预 | 不可能 | 钩子 B |
| 本地执行 | 必须调模型 | 0 请求 |
| 权限边界 | 无 | 白名单 + 配额 + 审计 |
| 可测试 | 无法断言 | 200+ 条断言，CI 强制 |
| 质量把关 | 只能影响生成过程 | 能检查结果是否达标 |

核心差异一句话：skill 分享「怎么做」，模块分享「做得好不好」。

## 五、与 agent 的关系

不是能力差距，是判断权归属不同。

| | agent | 本框架 |
|---|---|---|
| 谁判断「够不够好」 | 大模型（通用智能） | 模块（人编码的领域标准） |
| 判断成本 | 每轮 token | 规则≈0，小模型 50-500ms |
| 一致性 | 概率性 | 确定性 |
| 出错时 | 无法追问依据 | 能指出违反第几条 |
| 新增判断 | 改提示词（影响全局） | 加一个模块（互不干扰） |

循环可以打开（B 发现不合格 → 交给 A → 多一轮），但默认单轮，因为对话场景里响应速度优先。

## 六、三层能力

| 层 | 做什么 | 成本 | 当前状态 |
|---|---|---|---|
| L0 规则 | 算数、格式、脱敏、清单核对 | 0 | 已用 |
| L1 本地小模型 | 窄领域判断 | 50-500ms | 规划 |
| L2 云端大模型 | 通用理解与生成 | 1 请求 | 已有 |

原则：能用 L0 的不用 L1，能用 L1 的不用 L2。

## 七、明确不做

| 不做 | 原因 |
|---|---|
| 通用 agent（多步规划、长循环） | 移动端用户等不了，且是红海 |
| 端侧大模型（9B 级） | 为「选模块」加载 500MB，收益远低于成本 |
| UI 花活 | demo 已冻结，一律在 Compose 重做 |
| 自动修改用户原话 | 落库用原文，改写只用于组包 |

## 八、功能取舍的唯一判据

> 这个功能精修的是哪一侧？A、B，还是两侧都有？

答不出来 → 不做。
答得出 → 明确它落在哪一层（L0/L1/L2）、能在线验还是必须真机。
